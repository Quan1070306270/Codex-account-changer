# 本机 Token 用量采集（切换器 1.7.0）

- Mac 和 Windows 共用 `local/usage-collector.ts`。服务器在下载时自动去除类型标注并继续使用兼容文件名 `usage-collector.mjs`，因此现有切换器无需改变；安装器准备独立 Node 22 运行环境，下载后校验官方 SHA-256。
- 切换器启动一个受父进程生命周期约束的后台采集器，每分钟扫描一次；不启动模型请求、不修改 Codex 日志或登录状态。
- 读取当前操作系统用户的 `CODEX_HOME`（未设置时为 `~/.codex`）下 `sessions` 和 `archived_sessions` 的 JSONL。只解析 `event_msg / token_count`，仅发送哈希 ID、发生时间（秒）及 Token 数。
- 用量采用累计计数的增量；首次记录或计数下降时使用该条的 `last_token_usage.total_tokens`，相同累计值不重复计入。总量包含缓存输入，不能把缓存或推理子项再次相加。
- 初次升级最多回填近 14 天仍保留的记录；没有日志、关闭日志或不在该用户目录下的会话无法统计。数据不等于官方额度百分比，Plus 折算是经验估算。
- 每个文件按字节保存读取位置，单轮最多读取 8 MiB；不完整尾行下次再读。确认写入服务器后才推进位置；失败会重试。
- 服务端设备鉴权，批次最多 250 条，限制大小和时间；按事件指纹去重，同一份日志重复扫描、归档、跨设备复制不会累加。该指纹由原始时间戳及计数生成，不包含对话或文件路径。
- `device-usage.json` 保存近 14 天事件和设备上报状态。服务器汇总每半小时数据，网页每日图按浏览器时区和设备归类，不将旧记录错误归属到设备当前登录账号。
- 原官方累计采样文件保留兼容备份，不与本机事件相加。账号额度刷新仍为 5 分钟，网页图表读取仍为 30 秒。

更新：在网页每台设备旁点击“更新切换器”，在对应电脑运行命令。已有配对身份与本机游标保留。网页用量区会显示“用量已同步”或最近上报时间。

排查：设备本地 `GPTAccountSwitcher/usage-status.json` 是采集状态，`usage-cursors.json` 是进度；不含对话。首次回填可能需要几分钟。不要把某台电脑未升级或离线导致的缺失当作零消耗。
